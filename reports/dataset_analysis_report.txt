7. IMPORTANT OBSERVATIONS & MODELING RECOMMENDATIONS (FOR STAGE 3+)
--------------------------------------------------------------------------------
1. Country Blocking Strategy:
   - Real-world businesses do not cross national jurisdictions in this dataset.
   - Blocking by exact country code ('US', 'India', 'France') is completely safe and reduces the
     cross-product comparison space by >60%, drastically accelerating candidate generation.

2. The 'France' Out-of-Distribution Challenge:
   - 14.4% to 15.0% of test records belong to France, but NO French records exist in training data.
   - Any supervised classifier trained strictly on English/Hindi name patterns might misclassify French syntax.
   - Remedy: Candidate generation and feature computation must use language-agnostic text representations
     (character n-grams, Levenshtein/Jaro-Winkler via RapidFuzz, token sort/set ratios) and French-aware
     corporate abbreviation cleaning (e.g., 'SARL', 'SAS', 'SA', 'EURL', 'RUE', 'BD', 'AV').

3. Multilingual Handling (Hindi & Devanagari):
   - ~1.8% of Indian records contain Devanagari Hindi text.
   - Unicode normalization (NFKC) and script-aware tokenization are required.

4. Handling Source 3 Address Sparsity:
   - ~2.0% of records in Source 3 have empty business_address fields.
   - Matching algorithms must support fallback matching based purely on business_name and country
     without crashing on missing addresses.

5. Optimizing for the F0.5 Evaluation Metric:
   - F0.5 weights precision twice as heavily as recall: F0.5 = (1 + 0.5^2) * (P * R) / (0.5^2 * P + R)
   - A false positive penalty is substantially higher than a false negative penalty.
   - In ground truth, 5.58% of Source 1 entities have ZERO matches, and 25-27% of S2/S3 entities are singletons.
   - Conservative thresholding and high-precision confirmation rules will directly boost competition score.

6. Scalability & Memory Management:
   - With 1.7M Test S1 records and ~10M Test S2+S3 records, brute force would require 17 trillion comparisons.
   - A multi-tier indexing/blocking pipeline (Country Partition -> Inverted Index on Name Tokens ->
     Prefix/Soundex/MinHash -> Top-K RapidFuzz Verification) is required to finish within competition runtime.
