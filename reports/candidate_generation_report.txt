3. CANDIDATE GENERATION IMPROVEMENTS & MECHANICS
--------------------------------------------------------------------------------
1. Single-Pass Streaming In-Flight Pruning:
   - Dynamically deletes inverted lists and records high-frequency tokens into hash sets
     as soon as block size exceeds max_name_df (400) or max_addr_df (150).
   - Eliminates multi-gigabyte record buffers; enables indexing 5.03M records with < 1.7 GB RAM.
2. Numeric Address Token Matching:
   - Inverted index now extracts numeric tokens (len >= 2) such as street/plot numbers
     ('729', '314', '206', '11', '79').
   - Crucial bridge for cross-script Indian entities where the business name is written in an
     Indic script (Kannada, Hindi, Tamil) in S2/S3 but in English in S1, yet the building/plot
     numbers are identical in Arabic numerals.
3. Query Token Expansion:
   - Increased max_tokens_to_query from 2 to 3 for both name and address tokens.
   - Recovers entities with 3-token names where one token has a typo or corporate variation.
4. Multi-Tier Deterministic Tie-Breaking:
   - Ties among equal-scoring candidates are broken by pass diversity, presence of exact name,
     presence of name token, and stable entity ID ordering, avoiding random truncation.
